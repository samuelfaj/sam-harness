# Installed agent system

Use the repository-local context generated by Sam Harness after an approved application. These files route work and preserve review evidence; they do not grant new authority or prove that a command passed.

## Select local instructions

Read the root `AGENTS.md` and the closest `<workspace>/AGENTS.md` for the workspace you will touch. Sam Harness adds a bounded managed block to each detected non-root workspace; it preserves any user-authored content. Nested contracts keep workspace commands and boundaries near their code. If a managed block cannot coexist safely with existing instructions, stop and plan again instead of replacing the file.

## Load one lifecycle skill

Repository-local Agent Skills live at `.agents/skills/sam-harness-<lifecycle>/SKILL.md` for `classify`, `context`, `plan`, `implement`, `review`, `repair`, and `release`. Load only the skill for the current lifecycle state:

- `classify` identifies the task, risk, affected workspaces, and authority boundary.
- `context` selects relevant repository instructions and evidence without loading the whole project.
- `plan` turns the requested outcome into commands, gates, proof, and stop conditions.
- `implement` makes only the approved scoped source change.
- `review` runs deterministic evidence first and coordinates the six read-only reviewer roles as a pre-merge gate over the exact base/head fingerprints and canonical patch hash.
- `repair` validates a current repairable receipt, runs in an isolated Git sandbox, applies only a freshly tested, budget-compliant delta to an unchanged target, and emits its correction-only patch and hash.
- `release` handles artifact, staging, production, observation, migration, rollback, and release cadence as separate states.

The canonical `.sam-harness/config.yaml` remains the source of executable argv and waivers. A local skill cannot replace a missing command, overrule the nearest `AGENTS.md`, or authorize an external action.

## Prepare human review

The generated `.github/pull_request_template.md` and `.gitlab/merge_request_templates/sam-harness.md` carry the evidence ladder and the human-facing UX checklist inside bounded managed blocks. Fill only states backed by the current commit, receipts, provider readback, artifact digest, environment, or observation window. Leave unavailable or future states unchecked.

The UX checklist applies when a user-facing surface changes. It does not turn source inspection or a screenshot of one state into complete interaction, accessibility, localization, or responsive proof. A completed template also does not replace the required pre-merge provider review or its remote approval readback.
